# 계산 원리

이 문서는 계산기가 확률을 어떻게 구하는지, 특히 헷갈리기 쉬운 E.G.O 부분을 순서대로 설명합니다.

## 1. 왜 단순 곱셈으로는 안 되나

인격 하나만 보면 쉽습니다. 픽업 인격이 3개라 1개당 확률이 0.4833%라면,
200연 안에 그 인격을 한 번이라도 뽑을 확률은 `1 - (1 - 0.004833)^200 ≈ 62%`입니다.

하지만 목표가 여러 개가 되면 세 가지가 서로 얽힙니다.

1. **천장은 "몇 개를 못 뽑았는지"에 따라 결과가 갈립니다.** 200연이면 천장이 1번이라, 목표 4개 중 3개 이상을 직접 뽑아야 성공입니다.
2. **E.G.O 확률이 중간에 바뀝니다.** 뭘 이미 가졌는지에 따라 픽업 E.G.O 확률이 0.65%였다가 1.3%가 되기도 합니다.
3. **E.G.O를 전부 모으면 인격 확률도 바뀝니다.** E.G.O 칸이 없어지면서 픽업 인격 합계가 1.45%에서 1.5%로 오릅니다.

그래서 "각각의 확률을 곱하기"로는 정확한 값이 나오지 않고, 지금 무엇을 가졌는지를 상태로 들고 다니며 계산해야 합니다.

## 2. E.G.O 확률이 바뀌는 방식

E.G.O 칸은 1회 추출당 1.3%입니다. 이 1.3%를 누가 가져가는지는 **아직 없는 E.G.O**가 무엇이냐로 정해집니다.
이미 가진 E.G.O는 다시 나오지 않기 때문입니다.

| 상황 | 픽업 E.G.O | 기존 E.G.O |
|---|---|---|
| 픽업도 없고, 기존 E.G.O도 남아 있음 | 0.65% | 0.65% |
| 픽업은 없고, 기존 E.G.O는 올컬렉 | 1.3% | 0% |
| 픽업은 얻었고, 기존 E.G.O가 남아 있음 | 0% | 1.3% |
| 전부 가짐 | E.G.O 칸이 사라짐 → 픽업 인격 합계 1.5% | |

예를 들어 못 가진 기존 E.G.O가 5개라면, 처음에는 픽업 E.G.O가 0.65%뿐입니다.
뽑다가 기존 E.G.O가 나오면 하나씩 풀에서 빠지고, 5개를 다 뽑는 순간부터 픽업 E.G.O가 1.3%로 올라갑니다.
그래서 **올컬렉 여부에 따라 같은 200연이라도 성공률이 26.4%와 32.9%로 꽤 차이**가 납니다. (인격 4 + E.G.O 1 기준)

픽업 E.G.O가 여러 개면 픽업 몫(0.65% 또는 1.3%)을 아직 없는 픽업 E.G.O끼리 똑같이 나눈다고 가정했습니다. 이 부분은 인게임에서 확인되지 않은 가정입니다.

## 3. 상태로 계산하기 (동적 계획법)

결과에 영향을 주는 정보만 상태로 남깁니다.

| 기호 | 의미 |
|---|---|
| `i` | 아직 못 뽑은 목표 인격 수 |
| `t` | 아직 못 뽑은 목표 E.G.O 수 |
| `o` | 아직 못 뽑은 비목표 픽업 E.G.O 수 (목표는 아니지만 확률을 나눠 가지므로 필요) |
| `m` | 아직 못 가진 기존 E.G.O 수 |

"어떤 인격을 뽑았는지"가 아니라 "몇 개가 남았는지"만 들고 다니는 이유는, 목표 인격끼리 확률이 같아서 어느 것이 남았는지는 결과에 상관이 없기 때문입니다. 덕분에 상태 수가 작아져 1,000연 계산도 순식간에 끝납니다.

한 번 추출하면 상태는 다음 중 하나로 이동합니다.

```
(i, t, o, m) ─┬─ 목표 인격이 나옴        → (i-1, t, o, m)   확률: i × 인격 1개당 확률
              ├─ 목표 픽업 E.G.O가 나옴  → (i, t-1, o, m)   확률: 픽업 몫 × t / (t+o)
              ├─ 다른 픽업 E.G.O가 나옴  → (i, t, o-1, m)   확률: 픽업 몫 × o / (t+o)
              ├─ 기존 E.G.O가 나옴       → (i, t, o, m-1)   확률: 기존 몫
              └─ 그 외 (중복, 2성 등)     → (i, t, o, m)     확률: 나머지
```

시작 상태 확률을 1로 두고 이 이동을 N번 반복하면, N연 후 각 상태에 있을 확률이 나옵니다.
코드로는 `src/calc.js`의 `solve` 함수입니다.

## 4. 천장 반영

N연 후 남은 목표 수 `i + t`가 천장 횟수 `floor((현재 이상성 + N) / 200)` 이하이면 성공입니다.

이상성은 **마지막에 남은 목표에 몰아서 쓰는 게 가장 좋습니다.** 중간에 쓰면 나중에 자연스럽게 뽑힐 수도 있던 목표에 천장을 낭비할 수 있기 때문입니다.
그래서 계산도 "다 뽑고 나서 남은 것에 천장을 쓴다"로 했습니다.

## 5. 어떻게 맞는지 확인했나

`test/calc.test.js`에서 네 가지로 확인합니다.

- **닫힌 식 비교**: 인격 1~2개처럼 공식으로 풀리는 경우, 공식 값과 소수점 12자리까지 같은지
- **몬테카를로 비교**: 실제로 2만 번 뽑아 본 성공률이 정확 계산과 통계 오차(4 표준편차) 안에 드는지
- **확률 합**: 매 시점 모든 경우의 확률을 더하면 1인지
- **검증값**: 인격 4 + E.G.O 1에서 26.4% / 94.6% / 99.98%, 올컬렉 32.9% / 96.2%가 나오는지
